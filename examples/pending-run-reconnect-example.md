# 承認待ちのタスクを再送せずに確認する

## Scenario

問い合わせへの返信案を作成し、送信は担当者の承認を待つ運用です。担当者が応答を見る前にブラウザーが切断されました。タスクを作り直さず、既存のタスクがどこまで進んだかを確かめます。

## Input

```text
タスクID: demo-run-001（架空）
状況: 返信案の確認画面で接続が切れた
今回の権限: 同じタスクの状態を照会するだけ
```

## Agent Instruction

```text
読み取り専用で demo-run-001 の現在の状態と承認の有無を確認してください。
取得できた状態、取得時刻、次に担当者が判断することを返してください。
照会できなければ「未確認」とし、完了や失敗とは判断しないでください。
元の依頼の再送、新規タスクの作成、承認、メッセージ送信はしないでください。
```

## Expected Output Shape

```text
タスク: demo-run-001
状態: 承認待ち（同じIDで再接続時に照会）
取得時刻: 2026-11-24 08:30 JST（例）
送信: 未実行と記録されている
次の判断: 担当者が宛先と返信案を確認する
```

## Human Approval Boundary

- 元のタスクの照会は読み取り専用で行います。認証情報を入力例や報告に貼り付けないでください。
- 担当者の承認が必要なのは送信です。再接続や状態照会は承認の代わりになりません。
- 結果が分からないまま元の依頼を再送すると、二重実行になることがあります。まず元のタスクを確認してください。

[Open Agent API のローカル実測](https://github.com/Uky0Yang/awesome-ai-agents-zh/discussions/35)では、接続を切っても元のタスクIDから読み取りを再開でき、再実行せずに結果を確認できました。これはモデルや実際の顧客データを使わないテストで、顧客への送信を検証したものではありません。
